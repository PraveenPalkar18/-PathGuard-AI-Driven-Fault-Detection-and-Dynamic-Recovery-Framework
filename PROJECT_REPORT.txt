1. PROJECT OVERVIEW
================================================================================

PathGuard is an advanced SDN research framework built on Mininet. Its goal is to:
  - Create a programmable network topology with redundant paths
  - Continuously monitor network health (latency, packet loss) in real-time
  - Detect faults using machine learning (Random Forest classifier)
  - Support early-degradation warnings and rolling sliding-window metrics
  - Deliver unified 0-100 health scoring analytics
  - Automatically reroute traffic around failures using a custom deterministic POX SDN controller
  - Visualize live telemetry via an immersive HTML5/JS/CSS Dashboard Heatmap

Technology Stack:
  - Python 3, Mininet, Open vSwitch, POX SDN Controller
  - pandas, scikit-learn, joblib (AI/ML)
  - Flask (Web Dashboard REST API Backend)
  - HTML5, SVG CSS Heatmaps, Chart.js (Dashboard Visuals)

           h1    h2
            \   /
             s1          (OpenFlow 1.0 for POX compatibility)
            / \
           /   \

          |      |
          h4     h3

  - Switch s1: Port 1=h1, Port 2=h2, Port 3=s2, Port 4=s3
  - Switch s2: Port 1=h4, Port 2=s1, Port 3=s3
  - Switch s3: Port 1=h3, Port 2=s2, Port 3=s1

KEY COMPONENTS:
  - PathGuardTopo class: Custom Topo with configurable BW/delay/loss
  - cleanup_mininet(): Auto-cleans stale state before starting
  - simulate_link_failure() / restore_link(): Programmatic link control
  - latency_probe(): ICMP ping wrapper
  - --monitor flag: Starts monitoring headlessly (blocking loop without CLI lock)

4. MODULE 2: NETWORK MONITORING & HEALTH (COMPLETED)
================================================================================

Files: monitoring/monitor.py, monitoring/health.py

DATA FLOW:
  Mininet hosts -> ICMP ping -> parse_ping() -> MonitorRecord -> CSV + terminal

STATUS LABELS:
  ok            - 0% loss
  partial_loss  - 0% < loss < 100%
  timeout       - 100% loss
  error         - Parse failure

KEY ENHANCEMENTS:
  - Rolling Sliding Window: Stores last 3 rounds per host pair via `deque`.
  - Early Degradation Detector: Compares current round against historical
    moving average. Flags an automatic warning if latency spikes by 2x+.
  - Centralized Health Scoring: Standardized 0-100 scoring formula factoring
    max packet loss, latency, explicit timeouts, and instability variance.
  - Adaptive Monitoring: Transitions daemon collection sleep frequencies
    dynamically (Normal = 10s, Warning = 3s, Critical = 1s).
  - Smart Fault Diagnosis: Automatically correlates simultaneous host-pair
    telemetry outages to deduce precisely which specific switch-to-switch
    bottleneck link (s1-s2, s1-s3, or s2-s3) is failing before API dispatch.

6. MODULE 4: DATA COLLECTION SCRIPT (COMPLETED)
================================================================================

File: collect_data.py

PURPOSE: Automated data collection that avoids concurrent-access crashes.
  Runs monitoring and fault simulation sequentially on a single thread.

WORKFLOW:
  1. Build topology, verify connectivity (pingall)
  2. PHASE 1: Collect 5 rounds of NORMAL traffic
  3. PHASE 2: For each of 3 link failures (s1-s2, s2-s3, s1-s3):
     a. Bring link down
     b. Collect 3 rounds of FAULT data
     c. Restore link
     d. Collect 2 rounds of RECOVERY data
  4. Save CSV and print summary

9. MODULE 7: DYNAMIC RECOVERY ENGINE (COMPLETED)
================================================================================

Files: recovery/recover.py, controller/pathguard_controller.py

PURPOSE: Real dynamic OpenFlow rerouting via custom SDN programming.

KEY FEATURES:
  - Deterministic Static Map: Custom controller app completely replaces standard
    l2_learning and Spanning Tree, mapping the hardware interfaces verified via
    ovs-ofctl directly to hosts on startup.
  - Web REST API Handler: Exposes `/reroute` at POX port 8080. Accepts JSON
    post payloads declaring link failures (e.g., `{"failed_link": "s1-s2"}`) and
    issues restoration resets when `{"failed_link": null}` is called.
  - Switch Flow-Mod Injection: Dynamically pushes OpenFlow 1.0 `ofp_flow_mod`
    commands to reprogram switch paths via alternate transit nodes instantly.
  - ARP Proxy Proxying: The custom controller intercepts broadcast ARPs and 
    proxy-replies locally using a hardcoded IP-to-MAC mapping, preventing loop
    floods in the full-mesh switch triangle.
  - Mininet Native Verification: Leverages the native `net` object directly inside
    the recovery script, invoking `net.get('h1').cmd('ping -c 3 -W 1 10.0.0.4')`
    to confirm packet delivery and achieve sub-second real network reconvergence.
  - SDN Reset-to-Normal Hook: Issues automated restoration REST API resets when
    links physically heal, resetting flow tables dynamically back to Full-Mesh.

10. FIXES & ARCHITECTURAL PATTERNS APPLIED
================================================================================

- Switches forced to use protocols="OpenFlow10" to ensure POX compatibility.
- Default SDN port aligned globally to 6633 (switched from 6653).
- Integrated cleanup_mininet() in topology startups to purge dead interfaces.
- Bypassed Python 3.12 webcore traceback error by setting `pox_cookieguard = False`
  in the SplitRequestHandler class to allow POST JSON body ingestion.
- Refactored manual subprocess pings into Mininet `net.cmd` calls to prevent
  testing environmental contamination and false verification successes.
- Eliminated STP/Broadcast Loop Risks by constructing a dedicated controller
  ARP Proxy that responds locally rather than flooding inter-switch links.
- Swapped generic dynamic-learning for deterministic flow-mod injections to
  facilitate Sub-Second research-grade failovers.
- Bound webcore to port 8080 in `run_pox.sh` to align with the standard REST setup.
- Eliminated startup race conditions in `run_demo.sh` via native `nc` port polling
  (port 6633) to guarantee POX binding before Mininet attempts connecting.
- Implemented robust process group cleanup using a Bash `kill 0` EXIT trap to 
  ensure all background daemons cleanly shutdown during an interruption.
