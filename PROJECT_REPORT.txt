1. PROJECT OVERVIEW
================================================================================

PathGuard is an advanced SDN research framework built on Mininet. Its goal is to:
  - Create a programmable network topology with redundant paths
  - Continuously monitor network health (latency, packet loss) in real-time
  - Detect faults using machine learning (Random Forest classifier)
  - Support early-degradation warnings and rolling sliding-window metrics
  - Deliver unified 0-100 health scoring analytics
  - Automatically recommend and reroute traffic around failures using POX STP
  - Visualize live telemetry via an immersive HTML5/JS/CSS Dashboard Heatmap

Technology Stack:
  - Python 3, Mininet, Open vSwitch, POX SDN Controller
  - pandas, scikit-learn, joblib (AI/ML)
  - Flask (Web Dashboard REST API Backend)
  - HTML5, SVG CSS Heatmaps, Chart.js (Dashboard Visuals)

NETWORK ARCHITECTURE:
           h1    h2
            \   /
             s1          (OpenFlow 1.0 for POX compatibility)
            / \
           /   \
          s2 -- s3
          |      |
          h4     h3

KEY COMPONENTS:

  - cleanup_mininet(): Auto-cleans stale state before starting
  - simulate_link_failure() / restore_link(): Programmatic link control
  - latency_probe(): ICMP ping wrapper
  - --monitor flag: Starts monitoring automatically with topology

4. MODULE 2: NETWORK MONITORING & HEALTH (COMPLETED)
================================================================================

Files: monitoring/monitor.py, monitoring/health.py

DATA FLOW:
  Mininet hosts -> ICMP ping -> parse_ping() -> MonitorRecord -> CSV + terminal

STATUS LABELS:
  ok            - 0% loss
  partial_loss  - 0% < loss < 100%
  timeout       - 100% loss
  error         - Parse failure

KEY ENHANCEMENTS:
  - Rolling Sliding Window: Stores last 3 rounds per host pair via `deque`.
  - Early Degradation Detector: Compares current round against historical
    moving average. Flags an automatic warning if latency spikes by 2x+.
  - Centralized Health Scoring: Standardized 0-100 scoring formula factoring
    max packet loss, latency, explicit timeouts, and instability variance.
  - Adaptive Monitoring: Transitions daemon collection sleep frequencies
    dynamically (Normal = 10s, Warning = 3s, Critical = 1s).

6. MODULE 4: DATA COLLECTION SCRIPT (COMPLETED)
================================================================================

File: collect_data.py

PURPOSE: Automated data collection that avoids concurrent-access crashes.
  Runs monitoring and fault simulation sequentially on a single thread.

WORKFLOW:
  1. Build topology, verify connectivity (pingall)
  2. PHASE 1: Collect 5 rounds of NORMAL traffic
  3. PHASE 2: For each of 3 link failures (s1-s2, s2-s3, s1-s3):
     a. Bring link down
     b. Collect 3 rounds of FAULT data
     c. Restore link
     d. Collect 2 rounds of RECOVERY data
  4. Save CSV and print summary

9. MODULE 7: DYNAMIC RECOVERY ENGINE (COMPLETED)
================================================================================

Files: recovery/recover.py, recovery/path_selector.py

PURPOSE: Implement the intelligent decision/reroute pipeline.

KEY FEATURES:
  - Path Recommendation: Leverages metrics from the monitoring daemon to score
    candidate alternatives (`Path_A`, `Path_B`, `Path_C`) on active health.
  - Self-Healing Trigger: Triggered automatically when `CRITICAL` faults arise.
  - Simulation Logging: Outputs "Smart path recommended: Path_X selected" to
    inform system operators while POX Spanning Tree executes link-layer failover.
  - Analytics Hub: Updates recovery analytics (`successful_recoveries`,
    `average_recovery_time`, `last_recovery`) within `recovery_metrics.json`.
  - System Timelines: Logs to the shared `results/events.log` timeline.

10. FIXES APPLIED DURING DEVELOPMENT
================================================================================

- Switches forced to use protocols="OpenFlow10" to ensure POX compatibility.
- Default SDN port aligned globally to 6633 (switched from 6653).
- Integrated cleanup_mininet() in topology startups to purge dead interfaces.
- Resolved POX DNS parser failures on Python 3 string vs byte parsing.
- Re-routed POX arguments to enforce `openflow.spanning_tree --no-flood`
  eliminating broadcast loops in full mesh topology.
- Corrected CSS background-clip cross-compatibility vendor prefixes.
- Standardized JSON schema generation across the manual simulator script and the
  real-time daemon to prevent visual dashboard discrepancies.
